## my_gets — gets 직접 만들기
```c
void my_gets(char * str, int n) {
    int i = 0;
    char c;

    for(i = 0; i < n - 1; i++) {
        str[i] = getchar();

        if(str[i] == '\n') break;
    }

    if(i == n - 1 && (c = getchar()) != '\n') ungetc(c, stdin);

    str[i] = 0;
}
```
```c
char str[30] = { 0 };
my_gets(str, SIZE(str));
```
- `getchar()`로 **한 글자씩** 읽어서 배열에 넣는다.
- `'\n'`(엔터)을 읽으면 `break`. 그 자리를 `str[i] = 0`(`'\0'`)이 덮어써서 **줄바꿈 없이** 문자열이 끝난다.
- 반복은 최대 `n - 1`번. 마지막 한 칸은 `'\0'` 자리로 남겨 둔다 → 배열 크기를 넘지 않는다 (gets의 단점 해결).

```
입력: abc⏎   (n = 30)

i=0 'a' → i=1 'b' → i=2 'c' → i=3 '\n' → break
str: [a][b][c][\n] → [a][b][c][\0]
```

- 참고: 정확히 `n - 1`글자를 입력하면 `'\n'`을 읽기 전에 반복이 끝나서 `'\n'`이 버퍼에 남는다. 30번 줄의 `ungetc` 줄은 이걸 처리하는 부분인데, 크게 중요하지는 않다.

### 여러 가지 버전
| 함수 | 방식 | 특징 |
|---|---|---|
| `my_gets` | `n - 1`글자까지 저장, `'\n'`에서 멈춤 | 배열 크기를 넘지 않는다 |
| `my_gets_1` | `'\n'`까지 **전부 읽고**, 앞의 `SIZE - 1`글자만 저장 | 넘치는 입력은 버린다. 버퍼가 항상 깨끗 |
| `my_gets_2` | `n`글자까지 저장 | ⚠️ 엔터 없이 `n`글자가 차면 `'\0'`을 넣을 자리가 없다 |
| `my_gets_3` | `my_gets`를 포인터(`*p`, `p++`)로 | 아래 "포인터 접근 vs 배열 접근" 참고 |

## to_upper — 소문자를 대문자로
```c
char * to_upper(char * str) {
    char * new = str;

    while(*str) {
        if ('a' <= *str && *str <= 'z') *str -= 32;
        str++;
    }

    return new;
}
```
```
입력: hello world

hello world
HELLO WORLD
```
- `while(*str)`: 지금 글자가 `'\0'`(값 0)이면 거짓 → 문자열 끝에서 멈춘다. C의 `if`/`while`은 **0이면 거짓, 0이 아니면 전부 참**(음수도 참).
- `'a'`(97) - `'A'`(65) = **32**. 소문자에서 32를 빼면 대문자가 된다. `*str -= 'a' - 'A';`로 쓰면 의미가 더 잘 보인다.
- 범위 검사 `'a' <= *str && *str <= 'z'`가 없으면 공백, 숫자도 32가 빠져서 깨진다.
- `str++`로 포인터를 옮기다 보면 **시작 주소를 잃어버린다.** 그래서 처음에 `new`에 저장해 두고 그걸 반환한다.
- 반환값이 있어서 `printf("%s\n", to_upper(str));`처럼 바로 쓸 수 있다 (`strcpy`가 `to`를 반환하는 것과 같은 이유).

## 포인터 접근 vs 배열 접근
```c
// 포인터로 접근                       // 배열로 접근
while(*str) {                         while (str[i]) {
    ... *str ...                          ... str[i] ...
    str++;                                i++;
}                                     }
```
`my_gets`(배열)와 `my_gets_3`(포인터)을 어셈블리로 비교했다.

**최적화 없이(`-O0`)**: 포인터가 짧다
```asm
; str[i] — 접근할 때마다 주소를 새로 계산 (4줄)
mov    eax,DWORD PTR [rbp-0x4]    ; i
movsxd rdx,eax
mov    rax,QWORD PTR [rbp+0x10]   ; str
add    rax,rdx                    ; str + i

; *p — 이미 주소라서 1줄
mov    rax,QWORD PTR [rbp+0x10]   ; p
```

**최적화(`-O2`)**: 거의 같다
- 컴파일러가 `str[i]`를 **알아서 포인터 증가 방식으로 바꾼다.** 반복 한 번에 명령어 1줄 차이이고, 그 안의 `getchar()` 호출이 훨씬 비싸다.

| | 배열 `str[i]` | 포인터 `*p`, `p++` |
|---|---|---|
| 읽기 | 몇 번째 칸인지 바로 보인다 | 지금 어디인지 따라가야 한다 |
| 몇 글자 읽었나 | `i` | `p - 시작주소` (시작 주소를 따로 저장해야) |
| 성능 (`-O2`) | 같다 | 같다 |

👉 성능은 컴파일러가 맞춰 주니 **읽기 쉬운 쪽**을 쓴다. 포인터는 `while(*p)`처럼 끝까지 훑는 문자열 처리에서 자연스럽다.
